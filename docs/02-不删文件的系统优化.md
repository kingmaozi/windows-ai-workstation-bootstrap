# 02 不删文件的系统优化：Win11 专业工作站与 ZCode 交接

> 状态：建议稿，未在任何目标机实施。适用对象为全新 PC（不是当前 Mac）：Windows 11 Pro for Workstations x64，i9-13900KS，ASUS ROG MAXIMUS Z790 APEX，RTX 4090 24GB（水冷），DDR5 16GB×2 8000 CL36。本文只定义安全初始化与可逆优化的规范，所有结论以目标机实测和授权为准。

## 1. 目标与总原则

目标：不主动删除、移动或覆盖用户既有文件、应用环境与项目，在新目录完成初始化；系统设置只做窄范围、留旧值的变更。安装器/系统更新会写自身程序文件，不能承诺任何系统文件都不变或绝对零风险。原则是“先快照、后动作；每项设置有前后证据和回退方法；不能可靠回退的优化不自动做”。

版本策略：Win11 Pro for Workstations 已选定并沿用，不降级为 Pro/Home，不重装换版。系统未激活时只记录状态，不做任何激活破解、KMS 私服或授权文件修改；受影响的功能项准确标记为阻塞，其他不依赖授权的只读检查与可逆设置继续。无用户授权时不猜测、不代替确认，只把“缺什么、卡在哪、如何继续”写清楚。

## 2. 硬性禁止（红线）

- 禁止删除、移动、重命名用户文件；禁止 clean、debloat、卸载器、注册表清理、磁盘“优化”、一键加速类工具；禁止格式化、重建分区、覆盖 WIP、工程、素材或旧版本目录。
- 未知盘符、未知分区、外接盘一律只读探测（容量、文件系统、卷标），不写入、不初始化、不分配盘符。
- 禁止关闭 VBS/内存完整性、禁止设置 TDRDelay、禁止改 HPET、禁止“注册表加速”、禁止批量禁用计划任务、禁止为省空间关闭休眠文件。
- 禁止对整盘、用户目录或整个模型目录做 Defender 大范围排除；Defender、防火墙、SmartScreen、Windows Update 保持开启。
- 禁止自动迁移或清理 OneDrive、桌面、Downloads、凭据；禁止自动禁用全部启动项。
- 不运行来源不明的第三方“优化”脚本。第三方 installer 可能修改系统文件、服务与注册表，安装前必须确认来源、安装范围、会写入的位置和回滚方式，不能假设可逆。

## 3. 目录、备份与 ACL 纪律

所有新增内容写入版本化目录，例如 `D:\POD\bootstrap-20261019-v1\`；下一轮用 `-v2`，同一路径不原地覆盖。禁止把新文件写进用户既有工程目录。

改动前先做设置备份：`settings-backup\` 保存原电源方案、相关注册表项、服务与计划任务导出、已装软件清单，并记录 SHA256。含凭据的设置备份放在单独受限ACL目录并按需加密，不把秘密复制到可分享台账。复制权限/所有者可能需额外权限，先明确数据范围并验证目标保护，必要时单独导出SDDL/ACL；不递归复制整份用户profile，不使用镜像/清理/同步删除参数。含密码、令牌、Cookie 的文件单独标记，不写日志、不回显、不粘贴到聊天。

系统还原点不是文件备份：它不保护用户数据，不覆盖所有第三方改动，也不能保证零风险；只能作为额外一层，不能替代上述备份。创建还原点前若与既有策略冲突，只记录，不删除旧还原点。

## 4. 每项设置的证据与回滚格式

每条改动必须在 `changed-ledger.jsonl` 追加一条记录，不覆盖历史：

| 字段 | 要求 |
|---|---|
| id / 名称 / 时间 | 唯一，含时区 |
| 变更前快照 | 命令原文与原始输出，保存为文件 |
| 变更命令 | 完整可复制，禁止写“略” |
| 变更后快照 | 用同一命令复测并保存 |
| 判定 | 生效 / 未生效 / 部分生效 |
| rollback_commands | 恢复原值的完整命令 |
| 风险与依赖 | 是否需重启、是否影响登录、网络、睡眠 |

`rollback_commands.ps1` 默认 dry-run（`-WhatIf` 或仅打印），逐条可单独执行，执行前人工确认。回滚只恢复被修改的设置值，不自动卸载软件、不删除新增文件或新建目录、不回滚用户数据；新增文件是否清理由用户另行决定并单独审计。

## 5. 允许的优化（按顺序，必须有证据）

### 5.1 系统与驱动

联网后先完成 Windows Update 正常更新，保留更新与维护窗口，不无限推迟；记录系统版本与补丁号。芯片组、网卡、声卡、蓝牙使用 ASUS Z790 APEX 官方页面对应型号的原版驱动，版本必须匹配，不用第三方驱动包；GPU 使用 NVIDIA Studio 驱动，记录版本与安装来源。驱动回滚用设备管理器“回退驱动程序”或官方旧版安装包，不擅自使用第三方卸载工具。BIOS 只刷官方稳定版；13900KS 相关微码或修复按 ASUS 官方说明人工执行，崩溃、温度异常等症状不等于 CPU 已损坏，不据此下结论、不擅自降频或超频。XMP只读取当前值，不假定当前关闭/Auto，也不为本次初始化自动开启或关闭。DDR5-8000属超频档，用户当前已用的档位不等于长稳通过；确有错误时先报告证据，调整另行确认并单独验证。

### 5.2 电源方案

先读取并导出，不直接改原方案：`powercfg /getactivescheme`、`powercfg /query`、`powercfg /export <备份.pow> <GUID>`。用 `powercfg /duplicatescheme <原GUID> [新GUID]` 复制出新方案，只在副本上调整，原方案保留且不改名。仅在交流供电下建议睡眠 0 分钟、显示器 10 或 15 分钟；这是建议值，必须 target validated（在目标机复测并记录）后才算生效，电池与睡眠策略不动。保持 Balanced 或原方案，不强推 Ultimate Performance，不把处理器最小状态设为 100%，不用 `powercfg /h off` 关闭休眠文件省空间。回滚优先执行 `powercfg /setactive <原GUID>`；原方案真的缺失才评估导入备份。导入成功还需读取新GUID并显式激活、复测，不能把“导入了”当恢复完；副本不自动删除。

### 5.3 页面文件与内存

32GB物理内存搭配4090 24GB，视频模型offload主要消耗系统RAM；页面文件只是提交内存兜底，不是显存扩容或流畅推理保证。默认保留现有系统管理页面文件；若原来被禁用或有自定义位置，先记录并评估后再按授权更改，不自动迁盘。相关卷保留充足余量（系统盘建议至少100GB且按模型峰值调整，低于阈值停止大写盘任务并告警）。禁止关闭 pagefile，禁止固定为 0。不运行 RAM cleaner、内存整理或清空待机列表，不关闭内存压缩。

### 5.4 ComfyUI 与软件清单

使用原生 ComfyUI（官方仓库或官方便携包），默认单 GPU、batch size=1；32GB 内存下保留 offload，`--lowvram`/`--normalvram` 按实际显存与模型调整，不照抄参数，不承诺出图时长。软件清单保持最小：系统更新、ASUS 官方驱动、NVIDIA Studio、ComfyUI 依赖、浏览器、7-Zip、按需 Git、ZCode。每项记录来源、版本、安装路径；不装运行库合集、不多套 Python 污染 PATH，确需多环境时用独立虚拟环境并记录。不自动下载大型模型或权重，存储与带宽由用户确认。

### 5.5 启动、后台与守护

后台任务用计划任务 AtStartup（触发器“启动时”），以服务账户运行，不依赖用户登录；但 ZCode 或代理 GUI 可能登录后才可用，交接中必须区分“系统级任务/服务”和“用户会话 GUI”。定义两种状态：离线本地生成不依赖网络，登录后或服务身份可继续；网络作业等待网络与代理就绪，不静默失败，写出状态、重试上限和停止条件。服务身份、代理启动、凭据存放另稿统一，避免多处冲突。守护保留 Windows Update 维护窗口，更新期间暂停作业而不是禁用更新；保留手动 PIN/人工确认阻塞点，未确认不自动继续。不自动禁用全部启动项，只处理有证据且可回滚的单个项。

### 5.6 安全与存储

Defender、防火墙、SmartScreen、Windows Update 全部保留。本初始化默认不新增Defender排除。即使性能测试提示扫描开销，也先报告而不是自动加单程序排除；任何安全例外均需用户另行授权并评估，不对整个模型或用户目录排除。存储优化只做余量告警：监控各盘剩余空间与增长趋势，达到阈值提示用户；不自动清理、不自动迁移 OneDrive/桌面/Downloads/凭据，不扩大存储感知的自动删除范围；如开启存储感知，逐项记录并关闭自动删除下载、回收站等破坏性选项。

## 6. 验收

1. 所有改动都有 before/after 快照和 ledger 条目，命令可复制复现。
2. `rollback_commands.ps1` 在 dry-run 下可解析；至少抽取一项非关键设置实际回滚并复测，不能实测的写明原因。
3. 重启后可登录，网络与驱动正常；ComfyUI 单卡 batch1 可启动并加载模型；页面文件为系统管理且磁盘余量达标；电源仍为预期方案，休眠未关闭；Defender、防火墙、SmartScreen 为开启。
4. 对比改动前后的用户文件清单与抽样哈希，无文件缺失或内容变化；发现异常立即停止后续改动并报告。

验收以命令输出、日志和时间戳为证据，不以“看起来正常”为准。

## 8. ZCode 交接包

建议目录 `D:\POD\bootstrap-20261019-v1\handoff\`：

- `machine-profile.json`：硬件、Windows 版本与激活状态（只记录）、BIOS 版本、驱动版本、磁盘容量与余量。
- `source-snapshot\`：改动前 powercfg 导出、注册表/服务/计划任务导出、软件清单、用户文件清单与抽样哈希。
- `changed-ledger.jsonl`、`rollback_commands.ps1`、`README.md`：执行顺序、需人工确认项、回滚步骤。
- `blockers.md`：准确阻塞，例如激活无授权、BIOS 需人工、XMP 待定、模型权重未下载；写清缺什么、谁能做、完成后如何继续，不绕过。
- `verification\`：验收命令输出、时间戳与结论。

交接规则：ZCode 只按 ledger 继续；遇未授权项停下并登记，不猜测、不代替用户接受许可或激活；新增目录版本化，不覆盖上一版；任何回滚先 dry-run，再人工确认。
